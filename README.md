# 팀사주 (TeamSaju)

> 팀원 생년월일시를 넣으면 개인 사주와 팀 오행 조합을 뽑아서 협업 리포트를 만들어 주는 웹

푸른핫가마(T-BluePot) 서브 프로젝트

## 뭘 만드나

팀원 생시를 넣으면 세 가지가 나온다.

1. **개인 사주 카드** 여덟 글자, 오행 분포, 협업 성향 5축
2. **팀 오행 지도** 뭐가 넘치고 뭐가 비었나
3. **팀 리포트** 우리 팀이 어떤 유형인지, 이번 주에 뭘 해볼지

밖으로 나가는 건 3번뿐이다. 개인 사주 카드와 이름은 브라우저 안에만 있고,
공유 이미지에는 팀 단위 집계만 들어간다.

## 왜 만드나

사주 앱은 죄다 1인용이고 결과가 "올해 재물운" 같은 점술로 끝난다. 팀 단위로 보는 게 없다.
MBTI 팀빌딩은 이미 질렸고, 팀 워크숍에서 아이스브레이킹 소재는 늘 모자란다.

## 핵심 설계: 계산과 해석의 분리

```
생년월일시 → [사주 엔진(코드)] → 팩트 JSON → [Claude 에이전트] → 리포트
              결정론, 테스트로 고정      간지·오행·십신    서사만 담당
```

LLM한테 "1993년 5월 3일 사주 봐줘" 하면 **간지를 지어낸다.**
그래서 여덟 글자는 절기 테이블로 코드가 확정한 뒤 AI에 넘긴다.
API 키가 없어도 룰 기반으로 리포트가 나온다.

## 팀 유형 21가지

팀 오행 분포에서 주도 오행과 결핍 오행을 뽑아 유형을 정한다.

| 주도 | 결핍 | 유형 |
|---|---|---|
| 火 | 金 | 브레이크 없는 팀. 가속만 있고 제동이 없다 |
| 木 | 金 | 끝을 못 보는 팀. 시작한 건 열 개, 끝낸 건 하나 |
| 水 | 金 | 결론이 안 나는 팀. 회의 두 시간, 정해진 건 다음 회의 날짜 |
| 土 | 火 | 체온이 낮은 팀. 다 잘 돌아가는데 아무도 안 즐겁다 |

유형마다 강점 2개, 사각지대 2개, 이번 주에 해볼 처방 2개, 그리고
"이 팀에 들어오면 좋은 사람"이 붙는다.

## 기술 스택

새 스택을 고르는 대신 `barogagi-front` 가 쓰던 걸 그대로 가져왔습니다.
팀이 이미 아는 도구여야 리뷰가 빨라집니다. 다만 항목마다 이 프로젝트에서
왜 이게 맞는지는 따로 봤습니다.

| 레이어 | 선택 | 왜 이걸 골랐나 |
|---|---|---|
| 빌드 | Vite 8 | SEO가 필요 없는 도구형 SPA라 SSR 프레임워크가 과하다. HMR이 빨라 UI를 자주 만지는 이 프로젝트에 맞는다 |
| 프레임워크 | React 19 + TypeScript | 팀 전원이 쓰는 스택. 사주 계산 결과가 타입으로 고정돼야 화면에서 실수가 안 난다 |
| 스타일 | Tailwind CSS v4 | 디자인 토큰을 CSS 변수로 두고 유틸리티로 조립한다. 다크모드와 오행별 강조색 전환이 변수 교체만으로 끝난다 |
| 상태 | Zustand 5 | 팀원 목록과 화면 단계만 들고 있으면 된다. Redux는 과하고 Context는 리렌더가 넓다 |
| 애니메이션 | Framer Motion | 차트가 차오르는 모션에 쓴다. 이미 팀 표준이라 새로 배울 게 없다 |
| 사주 계산 | lunar-typescript | 절기 시각 테이블을 내장한다. 절기는 천문 계산이라 직접 짜면 경계 출생자에서 틀린다. 의존성 0개라 번들에 딸려오는 게 없다 |
| 테스트 | Vitest | Vite 설정을 그대로 쓴다. 골든 테스트가 빨리 돌아야 계산을 자주 검증한다 |
| 배포 | Vercel | 정적 자산과 서버리스 함수를 한 번에 올린다. Sprint 2의 AI 프록시까지 같은 배포로 간다 |

안 고른 것도 이유가 있습니다.

| 후보 | 왜 뺐나 |
|---|---|
| Next.js | 검색 노출이 필요 없는 도구입니다. 서버 렌더링을 얻는 대신 복잡도를 지불할 이유가 없습니다 |
| 차트 라이브러리 | 그리는 게 오행 5각 레이더 하나뿐입니다. 60KB 의존성보다 SVG를 직접 그리는 게 가볍고 손댈 수 있습니다 |
| html-to-image | 공유 카드를 SVG로 거치면 한글 폰트가 환경 따라 깨집니다. canvas에 직접 그려서 시스템 폰트로 확실히 찍습니다 |
| 백엔드와 DB | v1은 아무것도 저장하지 않습니다. 저장할 게 없으면 서버도 필요 없습니다 |
| 상태 영속화 라이브러리 | 생년월일을 브라우저에도 안 남기기로 했습니다. 저장을 돕는 도구가 오히려 방해입니다 |

## 시작하기

```bash
npm install
npm run dev      # localhost:5180
npm test         # 골든 테스트 포함
npm run build
npm run lint
```

환경변수는 `ANTHROPIC_API_KEY` 하나뿐이고 필수가 아니다. 없으면 룰 기반으로 돈다.
`VITE_` 접두사로 넣지 말 것. 클라이언트 번들에 노출된다.

```

│   ├── lib/report/     팀 유형 카피, 룰 기반 리포트
│   ├── components/

```

## 개인정보

- v1은 **아무것도 저장하지 않는다.** localStorage도 안 쓴다. 새로고침하면 사라진다
- 생년월일은 서버로 전송하지 않는다
- 공유 이미지에는 이름도 생년월일도 들어가지 않는다
- 팀원 정보를 대신 입력할 때는 본인 동의를 받았는지 확인한다

상세는 `docs/06-privacy.md`.

## 이건 재미로 보는 콘텐츠입니다

사주는 대화를 만드는 도구다. 채용이나 평가 근거로 쓰라고 만든 게 아니다.
리포트에는 사람을 배제하는 표현이 들어가지 않고, 부정적인 지적에는 반드시
실행 가능한 제안이 함께 붙는다.

# 개발 규칙

barogagi 프론트엔드와 같은 규칙을 씁니다.

## 브랜치

| 브랜치 | 용도 |
|---|---|
| `main` | 배포되는 상태. 직접 커밋하지 않습니다 |
| `dev` | 개발 통합. 작업 브랜치가 여기로 병합됩니다 |
| `feat/{설명}` | 새 기능 |
| `fix/{설명}` | 버그 수정 |
| `design/{설명}` | UI 작업 |
| `refactor/{설명}` | 동작 그대로 두고 구조만 |
| `chore/{설명}` | 설정, 의존성 |
| `infra/{설명}` | CI, 배포 |

이슈 번호를 앞에 붙여도 됩니다. `fix/89-web-bar` 처럼요.

## 커밋 메시지

```
[TYPE] 설명 (#이슈번호)
```

| 타입 | 언제 |
|---|---|
| `[FEAT]` | 새 기능 |
| `[FIX]` | 버그 수정 |
| `[DESIGN]` | UI, 스타일 |
| `[REFACTOR]` | 동작 그대로, 구조만 |
| `[CHORE]` | 설정, 의존성, 빌드 |
| `[DOCS]` | 문서만 |
| `[TEST]` | 테스트 |
| `[INIT]` | 초기 세팅 |

```
[FEAT] 사주 계산 엔진과 골든 테스트 (#12)
[FIX] 월지 보너스가 두 번 곱해지던 문제 (#31)
[DESIGN] 결과 화면 오행 레이더 색 오방색으로 교체 (#40)
```

급한 수정은 이슈 없이 나갈 수 있습니다.

```
!HOTFIX: 배포 후 공유 카드 폰트 깨짐
```

두 타입이 섞이면 같이 씁니다. `[FEAT, FIX] 일정 시간 선택 모달 개선` 처럼요.
한 커밋에 한 가지만 담는 걸 원칙으로 합니다.

## PR

- `dev` 를 대상으로 엽니다. `main` 으로 가는 PR은 릴리스할 때만
- 제목은 커밋 메시지와 같은 형식
- `.github/PULL_REQUEST_TEMPLATE.md` 를 채웁니다
- **PR 본문 맨 아래에 바뀐 화면 캡쳐를 넣습니다.** UI나 디자인 작업은 예외 없습니다.
  화면 변경이 없는 작업이면 그렇다고 적습니다
- 리뷰어 한 명 이상 승인 후 병합
- Squash merge

## PR 전에 돌릴 것

```bash
npm test
npm run lint
npm run build
```

계산 로직을 건드렸으면 `/verify-engine` 을 한 번 돌립니다.
사용자에게 보이는 문장을 추가했으면 `/ethics-check` 를 돌립니다.

## 문서가 먼저입니다

코드와 `docs/` 가 어긋나면 문서를 먼저 고치고 코드를 맞춥니다.
특히 `docs/03-saju-spec.md` 는 계산 엔진의 기준 문서입니다.
골든 테스트의 기대값은 고치지 않습니다. 테스트가 깨지면 코드가 틀린 겁니다.
