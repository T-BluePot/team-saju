# AI 에이전트 설계

에이전트가 두 종류 있다. 헷갈리지 말 것.

- 개발용: `.claude/` 에서 우리가 코드 만들 때 쓰는 도구
- 런타임: `api/` 에서 사용자가 리포트 볼 때 도는 파이프라인

## 개발용 에이전트

### 원칙

1. 사주 도메인 지식은 스킬로 빼서 필요할 때만 로드한다. 에이전트마다 컨텍스트를 최소로.
2. 읽기 전용 에이전트와 쓰기 에이전트를 분리한다. 검증자가 구현자를 감시하도록.
3. 도메인 규칙은 스킬에, 작업 절차는 에이전트에. 중복해서 쓰지 않는다.

### 구성

```
.claude/
  agents/
    saju-engine.md      계산 로직 구현 (쓰기)
    saju-verifier.md    계산 검증 (읽기 전용)
    saju-writer.md      해석 카피, 프롬프트
    ui-builder.md       React, Tailwind 컴포넌트
    ethics-reviewer.md  윤리 감사 (읽기 전용)
  skills/
    myeongri/SKILL.md      명리학 도메인 지식
    report-voice/SKILL.md  리포트 톤앤매너
  commands/
    verify-engine.md    골든셋 회귀 검증
    add-member-case.md  테스트 케이스 추가
    ethics-check.md     전체 카피 윤리 스캔
  settings.json         권한 allowlist
```

### 책임

| 에이전트 | 권한 | 담당 | 제약 |
|---|---|---|---|
| saju-engine | 쓰기 | `src/lib/saju/**` | 순수 함수만. 수정하면 반드시 `npm test`. 테스트 기대값을 코드에 맞춰 고치는 건 금지 |
| saju-verifier | 읽기 전용 | 계산 결과와 명세 대조 | 구현자가 자기 코드를 검증하면 같은 오해를 반복한다. 산출물은 불일치 목록 |
| saju-writer | 쓰기 | `src/lib/report/**`, 프롬프트 | 계산 로직 수정 금지. 숫자가 이상하면 verifier에게 넘긴다 |
| ui-builder | 쓰기 | `src/components/**`, `src/pages/**` | 반응형, 다크모드, 접근성 필수. `src/lib/**` 수정 금지 |
| ethics-reviewer | 읽기 전용 | 사용자에게 보이는 모든 문자열 | 미래 단정, 배제 표현, 건강 수명 언급, 조언 없는 부정 지적을 잡는다 |

## 런타임 파이프라인

통짜 프롬프트로 "팀 사주 리포트 써줘" 하면 개인 분석이 뭉개지고 길이 제어가 안 되고
실패 지점을 못 찾는다. 역할을 쪼개면 각 단계가 좁고 검증 가능한 출력을 낸다.

```
SajuFacts[] (생년월일 없음)
   |
   v  1. Persona    개인 3문장 + 키워드 3개, 인원수만큼 병렬
   v  2. Synergy    팀 강점2 사각지대2
   v  3. Playbook   실행 제안 3개
   v  4. Editor     톤 통일 + 가드레일
   v  코드 정규식 필터
   |
   +-- 통과 -> 최종 리포트
   +-- 2회 위반 -> 룰 기반 폴백
```

| 에이전트 | 출력 | temp | max_tokens |
|---|---|---|---|
| Persona | `{summary, keywords[3], workStyle}` | 0.7 | 500 |
| Synergy | `{strengths[2], blindSpots[2], dynamic}` | 0.6 | 800 |
| Playbook | `{actions[3]}` 각각 `{title, why, how}` | 0.5 | 800 |
| Editor | 최종 마크다운 | 0.3 | 1500 |

모델은 `claude-sonnet-5`. Persona는 팀원 수만큼 병렬로 돌려서 8명이어도 지연은 1회분.
구조화 출력은 tool_use 스키마로 강제해서 JSON 파싱 실패를 막는다.

### 가드레일

모든 에이전트 시스템 프롬프트에 주입한다.

```
[절대 규칙]
1. 미래를 단정하지 마라. "~할 것이다" 금지, "~한 경향" 사용.
2. 사람을 배제하는 문장 금지. "부적합", "맞지 않는다", "협업 불가" 금지.
3. 건강, 수명, 질병, 사망 언급 전면 금지.
4. 금전적 조언 금지.
5. 부정적 지적은 반드시 실행 가능한 제안과 함께 쓴다.
6. 주어진 팩트(간지, 오행, 십신)만 근거로 쓴다.
   날짜를 추론하거나 새 간지를 만들어내지 마라.
7. 한국어, 존댓말. 팀원 이름을 직접 부른다.
```

Editor 뒤에 코드 레벨 정규식 필터를 한 번 더 둔다. LLM 자기검열만 믿지 않는다.

```ts
const BANNED = [/부적합/, /협업\s*불가/, /상극이라\s*안/, /질병/, /수명/]
// 적발되면 Editor 재호출 1회, 또 실패하면 룰 기반 폴백
```

### 폴백

| 상황 | 동작 |
|---|---|
| API 키 없음 | 요청 자체를 안 보내고 룰 기반 리포트를 바로 띄운다 |
| 5xx 또는 20초 타임아웃 | 룰 기반 전환 + "AI 해석 없이 표시 중" 배지 |
| 가드레일 2회 위반 | 룰 기반 폴백 |
| Persona 1명만 실패 | 그 인원만 룰 기반, 나머지는 AI |

사용자는 어떤 경우에도 에러 화면을 보지 않는다. 리포트는 항상 나온다.

### 비용

5인 팀 1회 기준 대략 입력 6.8K, 출력 2.6K 토큰. 회당 수 센트 수준.
시스템 프롬프트는 prompt caching을 걸어서 반복 호출 비용을 낮춘다.
