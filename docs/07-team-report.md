# 팀 리포트와 공유 설계

## 원칙

**개인은 안에서만 보고, 밖으로 나가는 건 팀뿐이다.**

| | 팀 내부 뷰 | 공유 뷰 |
|---|---|---|
| 어디서 | 브라우저. 입력한 사람과 옆에서 같이 보는 팀원 | 링크, 이미지, 마크다운 |
| 개인 사주 카드 | 있음 | 없음 |
| 이름 | 있음 | 없음 |
| 생년월일시 | 있음 | 없음 |
| 페어 케미 (누구와 누구) | 있음 | 없음. 집계 숫자만 |
| 팀 오행 분포 | 있음 | 있음 |
| 팀 유형과 처방 | 있음 | 있음 |

공유 뷰에는 개인을 특정할 수 있는 게 하나도 안 들어간다. 그래서 공유 버튼을 누를 때
동의를 다시 받을 필요도 없고, 링크가 어디로 퍼져도 문제가 안 생긴다.

## 왜 팀 유형이 공유 단위인가

개인 사주는 이미 흔하다. 검색하면 널렸고 공유해봐야 반응이 없다.
"우리 팀은 브레이크 없는 불꽃 팀이래" 는 다르다. 팀원들이 각자 자기 팀에서
해보고 싶어진다. 공유가 유입으로 이어지는 지점이 여기다.

## 팀 유형 판정

주도 오행과 결핍 오행 조합으로 정한다.

```
주도 = 비율이 가장 높은 오행
결핍 = 비율이 가장 낮은 오행
균형점수 >= 75 이면 결핍을 따지지 않고 균형형
```

5 x 4 = 20 조합에 균형형 1개를 더해 **21 유형**이다.
동점이면 월지 가중이 더 큰 쪽, 그래도 같으면 목 화 토 금 수 순서로 자른다.

### 오행이 팀에서 뜻하는 것

| 오행 | 팀에서 | 없으면 생기는 일 |
|---|---|---|
| 木 | 새 아이디어, 시작, 확장 | 하던 것만 반복한다 |
| 火 | 열정, 속도, 표현 | 불이 안 붙는다 |
| 土 | 안정, 중재, 축적 | 쌓이는 게 없다 |
| 金 | 기준, 결단, 마감 | 자르질 못한다 |
| 水 | 유연, 통찰, 질문 | 왜 하는지 안 묻는다 |

### 21 유형

| 주도 | 결핍 | 이름 | 한 줄 |
|---|---|---|---|
| 木 | 火 | 회의록만 두꺼워지는 팀 | 아이디어는 쏟아지는데 아무도 안 만든다 |
| 木 | 土 | 벌여만 놓는 팀 | 판은 계속 커지는데 밑이 비어 있다 |
| 木 | 金 | 끝을 못 보는 팀 | 시작한 건 열 개, 끝낸 건 하나 |
| 木 | 水 | 왜는 안 묻는 팀 | 열심히 가는데 어디로 가는지는 아무도 모른다 |
| 火 | 木 | 다음 판이 없는 팀 | 이번 건 끝내주는데 그다음이 백지다 |
| 火 | 土 | 재만 남는 팀 | 매번 불태우는데 남는 건 피로뿐이다 |
| 火 | 金 | 브레이크 없는 팀 | 가속만 있고 제동이 없다 |
| 火 | 水 | 다 같이 끓는 팀 | 회의가 토론이 아니라 화력전이 된다 |
| 土 | 木 | 작년과 똑같은 팀 | 잘 굴러간다. 삼 년째 똑같이 굴러간다 |
| 土 | 火 | 체온이 낮은 팀 | 다 잘 돌아가는데 아무도 안 즐겁다 |
| 土 | 金 | 아무것도 못 접는 팀 | 다 좋다고 하다가 일이 안 줄어든다 |
| 土 | 水 | 물이 안 도는 팀 | 탄탄한데 바깥 공기가 안 들어온다 |
| 金 | 木 | 다듬기만 하는 팀 | 품질은 완벽한데 새로 나온 게 없다 |
| 金 | 火 | 정답만 있는 팀 | 다 맞는 말인데 아무도 하고 싶어지지 않는다 |
| 金 | 土 | 칼날만 남은 팀 | 지적은 날카로운데 받아줄 여유가 없다 |
| 金 | 水 | 예외가 없는 팀 | 규칙 밖 상황이 오면 그냥 멈춘다 |
| 水 | 木 | 회의만 깊어지는 팀 | 분석은 훌륭한데 만들어진 건 없다 |
| 水 | 火 | 다들 알고만 있는 팀 | 상황은 다 파악했는데 아무도 안 움직인다 |
| 水 | 土 | 매번 새로 시작하는 팀 | 잘 바꾸는데 쌓인 게 하나도 없다 |
| 水 | 金 | 결론이 안 나는 팀 | 회의 두 시간, 정해진 건 다음 회의 날짜 |
| 균형 | 균형 | 다 있는데 안 움직이는 팀 | 빠진 게 없다. 그래서 아무도 안 나선다 |

유형 이름과 한 줄은 어느 팀이 봐도 웃을 수 있어야 한다.
비난처럼 읽히면 안 된다. `못한다` 는 팀을 탓하는 게 아니라 빈자리를 가리키는 표현이다.

### 유형 데이터 구조

이름과 한 줄만 문서에 두고 나머지 카피는 `src/lib/report/archetypes.ts` 에 둔다.

```ts
type Archetype = {
  id: string            // 'wood-no-metal'
  dominant: Element
  lacking: Element | null
  name: string          // '마감이 없는 팀'
  tagline: string       // 한 줄
  strengths: [string, string]
  blindSpots: [string, string]
  prescriptions: [string, string]   // 실행 가능한 처방
  needsPerson: string   // 이 팀에 들어오면 좋은 사람
}
```

사각지대는 반드시 처방과 짝을 이룬다. 지적만 하고 끝나는 문장은 안 쓴다.

예시 하나.

```ts
{
  id: 'fire-no-metal',
  dominant: '火', lacking: '金',
  name: '브레이크 없는 팀',
  tagline: '속도는 최고, 멈출 기준이 없다',
  strengths: [
    '결정이 빠르다. 회의가 길어지는 일이 거의 없다',
    '일단 해보고 고치는 데 거부감이 없다',
  ],
  blindSpots: [
    '시작한 일을 접는 기준이 없어서 벌려둔 게 쌓인다',
    '급하게 넘어가서 나중에 되돌아오는 비용이 생긴다',
  ],
  prescriptions: [
    '스프린트마다 "이번에 접을 것" 한 줄을 정하고 시작하세요',
    '머지 전에 체크리스트 한 장만 두세요. 사람이 아니라 문서가 브레이크를 잡게',
  ],
  needsPerson: '"그래서 언제까지요?" 를 자연스럽게 물어보는 사람',
}
```

## 리포트 구성

### 팀 내부 뷰

탭 3개.

1. **개인** 팀원 선택하고 사주 원국 4주, 오행 바, 십신 태그, 계산 근거
2. **팀 지도** 오행 레이더, 균형 점수, 과잉 결핍 배지, 페어 케미 매트릭스
3. **리포트** 아래 공유 뷰와 같은 내용 + 페어 케미 해설

### 공유 뷰

한 화면에 스크롤로 이어진다.

```
[히어로]
  팀 이름 (없으면 "우리 팀")
  N명   (1명이면 "아직 혼자")
  이 기운으로 팀을 만들면   (1명일 때만)
  ─────────────────
  브레이크 없는 팀
  속도는 최고, 멈출 기준이 없다

[오행 레이더]
  5각형 + 각 원소 비율
  균형 점수 62

[한눈에]
  넘치는 기운  火 34%
  비어 있는 곳  金 6%

[이 팀의 강점]  2개
[놓치기 쉬운 것]  2개, 각각 처방과 한 쌍
[이번 주에 해볼 것]  3개

[이 팀에 들어오면 좋은 사람]
  "그래서 언제까지요?" 를 자연스럽게 물어보는 사람

[조합 집계]
  상생 3쌍 · 비슷한 결 2쌍 · 긴장 1쌍
  (누가 누구인지는 안 나온다)

[푸터]
  재미로 보는 콘텐츠입니다
  우리 팀도 해보기 →
```

## 공유 방식

| 방식 | 담기는 것 | 스프린트 |
|---|---|---|
| 마크다운 복사 | 슬랙 노션에 붙여넣을 텍스트. 이름 없음 | 1 |
| 링크 | URL에 팀 이름, 인원 수, 오행 비율, 균형 점수만 인코딩 | 2 |
| 이미지 카드 | 히어로 + 레이더 + 강점 1줄. SNS 슬랙용 1장 | 3 |

링크에 들어가는 페이로드는 이게 전부다.

```ts
type SharePayload = {
  v: 1
  teamName: string      // 사용자가 정함. 비우면 "우리 팀"
  size: number
  elements: [number, number, number, number, number]  // 木火土金水 비율
  balance: number
  pairs: { generating: number; same: number; tension: number }
}
```

생년월일, 이름, 개인 간지, 개인 오행이 여기 없다는 게 핵심이다.
링크를 받은 사람은 이 숫자들로 같은 유형 판정을 다시 돌려서 리포트를 그린다.
서버 저장이 필요 없다.

## AI가 하는 일

룰 기반 유형 카피만으로도 리포트는 완성된다. AI는 그걸 이 팀에 맞게 다듬는다.

- 유형 카피는 21개 고정이라 여러 팀이 같은 문장을 본다
- AI가 실제 오행 비율과 십신 분포를 보고 문장을 팀에 맞게 바꿔 쓴다
- 예를 들어 같은 `브레이크 없는 팀` 이라도 金이 6% 인 팀과 0% 인 팀은 표현이 달라진다

AI에 넘기는 것도 집계값뿐이다. 개인 팩트는 팀 내부 뷰의 개인 탭에서만 쓴다.

## 흥미 요소 체크

공유가 되려면 받은 사람이 열어보고 싶어야 한다.

- [ ] 유형 이름만 봐도 무슨 팀인지 짐작이 되나
- [ ] 한 줄이 웃긴가. 비난처럼 읽히지는 않나
- [ ] 처방이 진짜 이번 주에 해볼 만한가. 뻔한 소리는 아닌가
- [ ] "이 팀에 들어오면 좋은 사람" 이 대화를 만들어내나
- [ ] 이미지 한 장만 봐도 내용이 전달되나

## 혼자 넣었을 때

1명이어도 막지 않는다. 뭐가 비었는지, 어떤 사람을 붙이면 되는지 알 수 있어서 그게 쓸모다.
대신 화면이 팀인 척하면 안 된다.

문제는 21개 유형 이름이 전부 "...팀" 으로 끝나고, 강점과 처방도 "팀 안에 이미 있다" 처럼
여럿을 전제로 쓴 문장이라는 점이다. 그렇다고 21세트를 1인용으로 다시 쓰는 건 과하다.

그래서 유형을 **"이 기운으로 팀을 만들면 이렇게 된다"** 로 읽게 한다.
프레이밍을 바꾸면 본문의 "팀" 이 전부 제자리를 찾는다.

| 자리 | 여럿 | 혼자 |
|---|---|---|
| 머리말 | 우리 팀 · 3명 | 우리 팀 · 아직 혼자 |
| 유형 위 | 없음 | 이 기운으로 팀을 만들면 |
| 유형 아래 | 없음 | 혼자 넣은 결과라는 안내 한 줄 |
| 분석 부제 | 팀 전체의 기운을 재봤습니다 | 기운을 재봤습니다 |
| 상세 부제 | 강점과 빈자리, 그리고 처방 | 이 기운이 팀이 되면 어떻게 되나 |
| 첫 섹션 | 이 팀의 강점 | 같이 하면 좋은 사람 |
| 강점 제목 | 이 팀의 강점 | 이 기운이 만드는 강점 |
| 조합 집계 | 그린다 | 안 그린다 |

균형형만 따로 본다. `needsPerson` 이 "이미 다 있습니다" 인데 이건 여럿이 모여서 고르다는
뜻으로 쓴 문장이다. 혼자한테 붙으면 앞뒤가 안 맞아서 다른 문구로 간다.

판정과 문구는 `src/lib/report/solo.ts` 한 곳에 둔다.
화면과 공유 카드가 같이 읽어야 해서다. 컴포넌트마다 `size === 1` 을 따로 쓰면
카피가 늘 때 한 곳을 빠뜨리게 된다.

## 유형별 강조색

결과 화면 색은 **주도 오행**을 따라간다. 넘치는 기운이 그 팀의 성격이라서다.
일러스트는 결핍 기준이라 둘이 반대를 가리키는데, 이게 맞다.
색은 뭐가 넘치는지를, 그림은 뭐가 없는지를 말한다.

다홍은 브랜드 색으로 남는다. 헤더 로고와 랜딩은 그대로고 결과 화면 안에서만 갈아끼운다.

| 주도 | 면과 선 (`--accent`) | 글자 (`--accent-deep`) |
|---|---|---|
| 木 | 청록 `#2f7d6b` | `#1f5a4c` |
| 火 | 다홍 `#d93a26` | `#a82a19` |
| 土 | 황토 `#c08a2e` | `#8a6220` |
| 金 | 회청 `#7c8188` | `#565b61` |
| 水 | 남색 `#2b3a55` | 같음 |

**글자용을 따로 두는 이유**가 있다. 오방색 원본을 한지색 배경에 글자로 올리면
土가 2.99:1, 金이 3.86:1 이라 4.5:1 에 못 미친다. 진한 값을 두면 土 4.93 부터 木 7.87 까지 올라간다.

**강조색을 면으로 깔고 그 위에 글자를 얹는 자리**도 있다. 인장, primary 버튼, 선택된 이름 칩이다.
여기는 면색으로 `--accent-deep` 을 쓰고 글자는 `--on-accent` 를 쓴다.

오방색 원본 위에 흰 글자를 놓으면 라이트에서 土 3.04:1, 金 3.92:1 로 안 읽힌다.
그렇다고 흰 글자로 고정할 수도 없다. 다크는 `--accent-deep` 자체가 밝아서
흰 글자면 土 2.21:1 까지 떨어진다. **글자색도 테마를 따라 뒤집어야 한다.**

| | 면 (`--accent-deep`) | 글자 (`--on-accent`) | 대비 |
|---|---|---|---|
| 라이트 | 진한 오방색 | 흰색 | 5.46 부터 11.42 |
| 다크 | 밝은 오방색 | `--paper` 어두운 잉크 | 5.53 부터 8.45 |

즉 토큰이 네 개다. `--accent` 면과 선, `--accent-deep` 글자와 강조 면,
`--on-accent` 그 면 위의 글자, `--accent-wash` 옅은 바탕.

다크에서는 오방색이 대체로 밝아서 원본을 글자로 그대로 쓴다. `--accent-wash` 는
12%면 火가 4.42:1 이라 10%로 낮춘다.

水만 예외다. 다크 `--el-water` `#6b83ad` 가 어두운 편이라 wash 위에서 4.03:1 이고,
wash 를 0%까지 낮춰 surface 에 놓아도 4.51:1 이라 여유가 없다.
농도로는 못 고쳐서 `#8098c4` 로 밝힌다. wash 위 5.12:1 이 된다.

구현은 `[data-element]` 속성 하나다. `ResultPage` 루트에 주도 오행을 걸면
CSS 변수가 상속돼서 아래가 전부 따라온다. 공유 카드는 canvas 라 변수를 못 읽으니
`ELEMENT_HEX` 와 `ELEMENT_HEX_DEEP` 을 같은 값으로 두고 직접 넘긴다.

## 누굴 데려오면 되나

결과를 다 읽고 나면 "그래서 누굴 데려와야 되는데" 가 남는데 그 답이 한 줄뿐이었다.
좌우로 넘겨보는 카드 네 장을 둔다.

**팔자 8글자까지 안 간다. 오행 하나로 말한다.** "금 기운이 센 사람" 이 더 잘 읽힌다.

축이 두 개다. 비어 있는 걸 채우느냐, 넘치는 걸 더하느냐.

| 카드 | 기운 | 좋은가 |
|---|---|---|
| 결핍을 채운다 | 결핍 오행이 센 사람 | 좋다 |
| 넘치는 걸 안 더한다 | 주도 오행이 약한 사람 | 좋다 |
| 넘치는 걸 더한다 | 주도 오행이 센 사람 | 안 된다 |
| 빈 데를 더 비운다 | 결핍 오행이 약한 사람 | 안 된다 |

균형형은 이 섹션을 안 그린다. 채울 데도 덜 데도 없어서 네 장을 억지로 만들면 같은 말이 두 번 나온다.

### 넘으면 안 되는 선

**실제로 입력한 팀원을 줄 세우지 않는다.** 누가 최고고 누가 최악인지 매기는 UI는
`docs/00-product-brief.md` 의 "궁합 점수로 사람 배제" 금지에 걸린다.
채용이나 평가 근거로 쓰이면 곤란한 종류다.

말하는 대상은 **아직 팀에 없는 가상의 기운**이다. 섹션 부제와 하단에 그렇게 적어둔다.

**안 되는 쪽에도 처방이 반드시 붙는다.** "이 사람은 안 된다" 로 끝나면 사람을 자르는 말이 된다.
"그래도 데려오고 싶으면 이렇게 하세요" 가 같이 가야 한다. 테스트로 고정했다.

문구도 사람이 아니라 **조합**을 얘기하게 쓴다. "뽑지 마세요" 가 아니라
"거기에 더 보태면 쏠림이 두 배가 됩니다" 다.

## 이 팀만의 변주

주도와 결핍 두 변수만으로는 3인 팀과 8인 팀이 같은 결과로 떨어진다.
같은 "브레이크 없는 팀" 이어도 아래가 다르면 다른 팀이다.

| 변주 | 조건 | 처방 |
|---|---|---|
| 밀어주는 짝이 없음 | 상생 조합이 0쌍 | 있음 |
| 혼자 도는 자리 | 상생에 안 들어간 자리가 있음 (3인 이상) | 있음 |
| 5축 공백 | 어느 축이 5% 이하 | 있음 |
| 다 밀어붙이는 쪽 / 다 맞춰주는 쪽 | 신강 또는 신약이 70% 이상 | 있음 |
| 작은 팀 / 중간 팀 / 큰 팀 | 3인 이하 / 4~6인 / 7인 이상 | 큰 팀만 |

인원수 구간은 항상 마지막이다. 늘 나오는 얘기라 앞에 두면 지겹다.
**혼자면 변주를 아예 안 그린다.** "한 명이 빠지면" 을 혼자인 사람에게 내밀 수 없다.

쏠리지 않은 팀에는 강약 변주를 안 붙인다. 89% 팀에 붙는 문장은 변주가 아니라 노이즈다.

상생이 아예 없으면 "혼자 도는 자리" 를 안 그린다. 같은 얘기를 두 번 하게 된다.

### 사람을 지목하지 않는다

누가 겉도는지 이름을 쓰면 배제하는 UI 가 된다. `docs/00-product-brief.md` 의
"궁합 점수로 사람 배제" 금지에 걸린다.

**"자리" 로만 말한다.** 처방도 그 사람을 어떻게 하라가 아니라 팀이 뭘 하라로 쓴다.
"그 자리를 없애는 게 아니라 짝을 붙이면 됩니다" 처럼.

테스트가 고정하는 건 **문구에 이름이 안 들어간다**는 것 하나다.
그 이상은 보장하지 않는다. 개인 탭이 멤버별 짝을 다 보여주기 때문에,
"혼자 도는 자리 하나" 를 본 사람이 개인 탭과 대조하면 누구인지 좁힐 수 있다.

그래서 문구와 처방은 **그 사람이 특정돼도 읽는 데 문제없게** 쓴다.
겉도는 게 그 사람 탓이라고 하지 않고, 팀이 짝을 붙이면 되는 일로 쓴다.
