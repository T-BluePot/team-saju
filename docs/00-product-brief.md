# 프로덕트 브리프

푸른핫가마 서브 프로젝트 · 코드네임 `team-saju`

## 뭘 만드나

팀원 생년월일시를 넣으면 세 가지가 나온다.

1. 개인 사주 카드 (8글자, 오행 분포, 성향 5축)
2. 팀 오행 지도 (뭐가 넘치고 뭐가 비었나)
3. 팀 리포트. 우리 팀이 어떤 유형인지, 뭐가 비었는지, 이번 주에 뭘 해볼지

**밖으로 나가는 건 3번뿐이다.** 개인 사주 카드와 이름과 생시는 브라우저 안에만 있고
공유 링크에는 팀 단위 집계만 담긴다. 상세는 07-team-report.md

## 문제

- 사주 앱은 죄다 1인용이고, 결과가 "올해 재물운" 같은 점술로 끝난다. 팀 단위로 보는 게 없다.
- MBTI, DISC 기반 팀빌딩 콘텐츠는 포화라 신선함이 없다.
- 팀 워크숍에서 아이스브레이킹 소재는 늘 모자란다.
- LLM은 서사는 잘 쓰는데 계산을 못 한다. 계산을 코드로 빼면 품질이 잡힌다.

## 쓰는 상황

| 언제 | 뭘 얻나 |
|---|---|
| 프로젝트 킥오프 | 5분 만에 팀 리포트 뽑고 웃으면서 서로 소개 |
| 스프린트 회고 | "왜 저 둘이 붙으면 일이 되지"에 설명이 붙음 |
| 태스크 분배 회의 | 십신 기반 역할 성향 제안. 강제 아니고 대화 촉진용 |
| 슬랙 공유 | 우리 팀 유형 카드 공유. 받은 사람이 자기 팀에서 해보고 싶어짐 |

타깃은 우리 팀 먼저, 그다음 5~8인 팀.
혼자 넣어보는 것도 정식 경로다. 뭐가 비었는지, 어떤 사람을 붙이면 되는지가 보인다.
대신 화면이 팀인 척하지 않는다. 조합 집계를 빼고 누굴 데려오면 좋은지를 앞으로 올린다.

## 경쟁 대비

| | 기존 사주 앱 | 팀사주 |
|---|---|---|
| 대상 | 개인 | 팀 1~8인. 혼자 넣어보는 것도 막지 않는다 |
| 결과물 | 운세 예측 | 협업 스타일 리포트 |

## 하지 않는 것

요청이 와도 v1에서 안 한다.

- 운세 예측 ("올해 재물운", "언제 이직"). 법적으로도 윤리적으로도 위험하다.
- 궁합 점수로 사람 배제. 채용이나 평가 근거로 쓰일 수 있는 UI는 절대 안 만든다.
- 회원가입, 서버 영구 저장, 결제
- 생년월일을 URL이나 서버 로그에 남기기
- 개인 사주 카드를 공유 가능하게 만들기. 공유 단위는 팀뿐이다
- 타로나 점성술 같은 다른 체계 섞기

## 윤리 가드레일

사주는 재미로 보는 대화 도구다. 이 프레이밍을 제품 곳곳에 박는다.

- 미래 단정 금지. "~할 것이다" 대신 "~한 경향".
- 사람 배제 표현 금지. "부적합", "협업 불가" 안 쓴다.
- 건강, 수명, 질병 언급 전면 금지.
- 부정적인 얘기는 반드시 실행 가능한 제안이랑 같이 쓴다.
- 생년월일은 서버로 안 보낸다. AI한테도 간지랑 오행만 넘긴다.
- 실제 생시는 동의를 받고 입력받는다. 대리 입력이면 팀원 본인 동의를 확인한다. 상세는 06-privacy.md
- 프롬프트 규칙 + 코드 정규식 필터 이중 방어. LLM 자기검열만 믿지 않는다.
