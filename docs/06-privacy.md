# 개인정보 처리 설계

생년월일시는 개인정보다. 그리고 이 서비스는 구조상 남의 생시를 모아야 한다.
이 문서는 그걸 어떻게 다룰지 정한다.

## 우리 위치

v1은 개인정보를 **서버로 보내지도, 디스크에 남기지도 않는다.** 열려 있는 탭의
메모리에만 있고 새로고침하면 사라진다. 그래서 우리는 개인정보를 보관하는 쪽이 아니다.

다만 이용자가 **제3자(팀원) 정보를 입력하는 구조**라서, 그에 대한 고지와 확인
절차를 제공할 의무는 우리한테 있다. 그게 아래 2단 동의다.

Sprint 3에서 서버 저장이나 초대 링크를 넣는 순간 우리가 처리자가 된다.
그때는 개인정보처리방침을 정식으로 쓰고 보유기간, 파기절차, 암호화를 설계한다.

## 수집 항목

| 항목 | 필수 | 쓰는 이유 |
|---|---|---|
| 이름 또는 별칭 | 필수 | 리포트에서 누구 얘긴지 구분 |
| 생년월일 | 필수 | 연주 월주 일주 계산 |
| 태어난 시간 | 선택 | 시주 계산. 없으면 3주만 분석 |

성별은 안 받는다. 대운 방향에 쓰려던 건데 대운 자체가 v1에 없다.
쓰지도 않을 개인정보를, 그것도 대리 입력으로 남의 것까지 받는 건 앞뒤가 안 맞는다.

이름은 실명이 아니어도 된다. 입력 폼에 "별칭도 괜찮아요"를 안내로 띄운다.

## 동의 구조

2단으로 나눈다. 한 번에 몰아서 받으면 대리 입력 문제가 묻힌다.

### 1단. 이용자 본인 동의 (최초 1회)

앱에 처음 들어오면 모달로 띄운다. 여기 없으면 입력 화면으로 못 넘어간다.

띄울 내용

- 수집 항목: 이름(별칭), 생년월일, 태어난 시간(선택)
- 이용 목적: 사주 계산과 팀 협업 리포트 생성
- 보관 위치: **어디에도 저장하지 않음. 서버로도 안 보내고 디스크에도 안 남김**
- 보관 기간: 없음. 탭을 닫거나 새로고침하면 그 자리에서 사라짐
- 거부 권리: 동의를 거부할 수 있음. 다만 거부하면 계산 자체가 불가능해서 서비스를 쓸 수 없음
- 만 14세 미만은 이용할 수 없음

필수 동의 체크박스 1개. 다크패턴 금지다. 기본값 체크 해제, 동의 버튼과 거부 버튼을
같은 비중으로 둔다.

### 2단. 팀원별 대리 입력 확인 (팀원 추가할 때마다)

이게 핵심이다. 팀원 카드에 라디오 2개를 둔다.

- `본인 정보입니다`
- `본인에게 동의를 받고 대신 입력합니다`

둘 중 하나를 안 고르면 저장 버튼이 비활성이다. 두 번째를 고르면 확인 문구를 붙인다.

> 팀원 본인에게 생년월일시를 팀사주에 입력한다는 것을 알리고 동의를 받으셨나요?
> 동의 없이 타인의 개인정보를 입력하면 법적 문제가 생길 수 있습니다.

팀원 카드에는 동의 출처 배지를 계속 표시한다. 본인이면 회색, 대리면 노란색.

## 동의 버전 관리

동의 내용이 바뀌면 재동의를 받아야 한다.

```ts
type AppConsent = {
  version: string      // 'v1.0'. 동의서 내용이 바뀌면 올린다
  agreedAt: string     // ISO datetime
}
```

저장된 `version`이 현재 버전보다 낮으면 모달을 다시 띄운다.

## 철회와 삭제

- 팀원 개별 삭제. 카드에서 바로 지운다. 즉시 메모리에서 빠진다.
- 탭을 닫거나 새로고침하면 전부 사라진다. 따로 지울 게 남지 않는다.
- 그래서 `모든 데이터 삭제` 버튼도 두지 않는다. 지울 저장소 자체가 없다.

삭제는 되돌릴 수 없다. undo 토스트는 팀원 개별 삭제에만 붙이고 전체 삭제에는 안 붙인다.

## 상시 고지

동의 모달은 한 번만 뜨지만, 데이터가 어디 있는지는 계속 보여야 한다.

- 입력 화면 하단: `입력한 정보는 이 브라우저에만 저장되며 서버로 전송되지 않습니다`
- 결과 화면 하단: 같은 문구 + `재미로 보는 콘텐츠입니다`

## 공유 단위는 팀뿐이다

개인은 안에서만 보고, 밖으로 나가는 건 팀 리포트뿐이다. 상세 설계는 `07-team-report.md`.

| | 팀 내부 뷰 | 공유 뷰 |
|---|---|---|
| 어디 있나 | 브라우저 안 | 링크, 이미지, 마크다운 |
| 개인 사주 카드 | 있음 | 없음 |
| 이름 | 있음 | 없음 |
| 생년월일시 | 있음 | 없음 |
| 페어 케미 (누구와 누구) | 있음 | 없음. 집계 숫자만 |
| 팀 오행 분포, 유형, 처방 | 있음 | 있음 |

이렇게 나누면 공유 경로에서 개인정보 문제가 통째로 사라진다.
공유할 때 동의를 다시 받을 필요가 없고, 링크가 어디로 퍼져도 상관없다.

### 원래 설계에서 뭘 바꿨나

F5.2는 입력값을 URL 해시에 담는 설계였다. 폐기했다.
URL 프래그먼트는 서버로 전송되지는 않지만 브라우저 히스토리, 북마크, 메신저
미리보기, 스크린샷에 남는다. 생년월일을 링크에 실어 보내는 건 위험하다.

링크에 담는 건 이게 전부다.

```ts
type SharePayload = {
  v: 1
  teamName: string      // 사용자가 정함. 비우면 "우리 팀"
  size: number
  elements: [number, number, number, number, number]  // 木火土金水 비율
  balance: number
  pairs: { generating: number; same: number; tension: number }
}
```

생년월일, 이름, 개인 간지, 개인 오행이 여기 없다. 링크를 받은 사람은 이 숫자들로
유형 판정을 다시 돌려서 리포트를 그린다. 서버 저장도 필요 없다.

팀 이름은 사용자가 직접 정하니까 실명 팀명을 쓸지 말지도 사용자가 정한다.
기본값은 "우리 팀" 이고, 입력 폼에 "외부에 공유할 수 있으니 편한 이름으로" 를 안내한다.

## AI 리포트와 개인정보

Sprint 2에서 Claude를 붙일 때도 원칙은 같다.

- 서버로 가는 건 `SajuFacts` 뿐. 이름, 간지 8글자, 오행 비율, 강약, 십신, 5축 성향
- 생년월일과 태어난 시간은 안 보낸다
- 서버 로그에 요청 본문을 남기지 않는다
- 이름을 보내는 게 걸리면 동의 모달에 `AI 리포트 사용 시 이름이 전송됩니다`를 명시한다

## 만 14세 미만

한국 개인정보보호법상 만 14세 미만 아동의 개인정보를 수집하려면 법정대리인 동의가
필요하다. 우리는 수집하지 않지만 절차를 만들 이유도 없으니 이용 대상에서 뺀다.

동의 모달에 `만 14세 이상만 이용할 수 있습니다`를 넣는다. 나이 검증은 하지 않는다.
검증하려면 오히려 정보를 더 받아야 해서 최소 수집 원칙에 어긋난다.

## Sprint 3 초대 링크 (예정)

각자 본인 생시를 직접 입력하는 게 법적으로 제일 깔끔하다. 다만 여러 명 데이터를
모으려면 서버가 필요해서 Sprint 3으로 미룬다.

그때 설계할 것

- 팀 대표가 초대 링크 생성. 링크에는 팀 ID만 들어가고 개인정보는 없다
- 팀원이 들어와서 본인 동의하고 본인 생시 입력
- 서버는 계산 결과만 저장하고 원본 생년월일은 저장하지 않는다
- 보유기간 설정. 기본 30일 후 자동 파기
- 팀원 본인이 언제든 자기 정보를 뺄 수 있는 경로 제공

이 시점에는 개인정보처리방침 문서를 정식으로 만든다.

## 체크리스트

새 기능을 붙일 때마다 이걸 본다.

- [ ] 생년월일 원본이 브라우저 밖으로 나가나
- [ ] URL이나 로그에 개인정보가 남나
- [ ] 제3자 정보를 입력받는 경로가 새로 생겼나
- [ ] 공유 뷰에 개인을 특정할 수 있는 게 들어가지 않았나
- [ ] 동의 항목이 바뀌었나. 바뀌었으면 버전을 올렸나
- [ ] 삭제 경로가 있나
